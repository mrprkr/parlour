title: Tuning
description: Wake sensitivity, how long it waits for you to finish, the voice, model sizes, and what to change when something is wrong.
---

Everything on this page is a key in `~/.config/parlour/config.json`.
`parlour config edit` opens the file, `parlour config show` prints what is
in force with the defaults filled in, and `parlour service restart` (or a
restart from the app) picks up whatever you changed.

## When something is not quite right

| What you notice | What to try |
| --- | --- |
| It wakes up for the television | Raise `wake.threshold` towards 0.7. |
| It never wakes up | Lower `wake.threshold` towards 0.4, and check `audio.inputDevice` is the microphone you think it is. |
| It cuts you off mid-sentence | Raise `audio.silenceMs`, or lower `audio.silenceThreshold`. |
| It waits too long before answering | Lower `audio.silenceMs` to about 600. |
| It gives up before you start talking | You have 2.5 s after the wake word to begin. Try saying the wake word and the request in one breath. |
| It answers slowly | Try a smaller local model, or a smaller whisper model: `parlour models fetch --whisper ggml-base.en.bin`, then `parlour service install` to rewrite the whisper service. It loads the first model file in `~/Library/Caches/parlour/models/whisper/`, and `base` sorts before `small`. |
| It asks the cloud too often, or not often enough | That is decided by the prompt rather than a threshold. See `packages/parlour/src/core/prompt.ts`. |
| It says nothing at all | Run `parlour doctor`, or press Check in the app. It will name the part that is down. |
| It talks over itself | `audio.bargeIn` is off by default because with one box in one room, the microphone hears the speaker. |
| It fires twice on one wake word | Raise `wake.refractoryMs`. |
| The voice is not the one you wanted | `tts.voice` and `tts.speed`. Kokoro downloads itself the first time Parlour starts after an install, so that first start is slow and the fallback voice may speak until it is ready. |
| It can see the lights but not the blinds | Expose the blinds. Home Assistant only publishes what is exposed under Settings > Voice assistants > Expose. |

## Audio

```json
{
  "audio": {
    "inputDevice": ":0",
    "silenceMs": 800,
    "maxUtteranceMs": 15000,
    "silenceThreshold": 0.012,
    "bargeIn": false
  }
}
```

- **`inputDevice`** is an avfoundation index, and `":0"` is the default
  microphone. `ffmpeg -f avfoundation -list_devices true -i ""` prints the
  list, and `parlour init` shows it to you when it asks.
- **`silenceMs`** is how much quiet ends a request once you have started
  talking. **`silenceThreshold`** is the RMS level, from 0 to 1, below which
  a frame counts as silence. A noisy room wants it higher; a quiet speaker
  wants it lower.
- **`maxUtteranceMs`** caps a single request. It is a limit for a microphone
  that never goes quiet, not a way to allow long questions.

## The wake word

```json
{ "wake": { "provider": "openwakeword", "words": ["hey_jarvis"], "threshold": 0.5, "refractoryMs": 1500 } }
```

The stock words are `hey_jarvis`, `alexa` and `hey_mycroft`, and
`parlour models fetch --wake hey_jarvis,alexa` fetches the ones you name into
`~/Library/Caches/parlour/models/openwakeword/`. Any openWakeWord model works:
drop `<word>.onnx` into that directory and add `<word>` to `words`. You can
have more than one word live at once, for a small cost in CPU. To train a
word of your own, see [Your own wake word](/docs/wake-word).

## The voice

```json
{ "tts": { "provider": "kokoro", "voice": "bf_emma", "speed": 1.0, "fallback": "macos-say" } }
```

Kokoro's British voices are `bf_emma`, `bf_isabella`, `bm_george` and
`bm_lewis`. If you name a voice it does not have, the reply falls through to
the fallback and the log lists every voice Kokoro knows. `fallback` names the
voice used when the first one fails (`null` turns the fallback off).
`macos-say` ignores a Kokoro voice id and uses the system voice, or you can
give it a macOS voice name of its own (`"voice": "Daniel"` when `provider`
is `macos-say`).

## The models

```json
{
  "llm": {
    "local": { "provider": "openai-compatible", "managed": true, "baseUrl": "http://127.0.0.1:8920/v1", "model": "qwen2.5-7b-instruct", "temperature": 0.3, "timeoutMs": 30000 },
    "cloud": { "provider": "anthropic", "enabled": true, "model": "claude-opus-5", "maxTokens": 1024, "onLocalFailure": true },
    "maxToolRounds": 6
  }
}
```

- **`local.managed`** is Parlour running the model itself: llama.cpp from
  Homebrew, a GGUF from its own catalogue, kept warm by launchd on port 8920
  exactly as whisper is. `parlour models suggest` lists the catalogue and
  says which one this Mac should hold; `parlour models fetch --llm <id>`
  downloads another. Turn it off and Parlour talks to whatever server
  `baseUrl` names instead, and starts none of its own.
- **`local.model`** is the id exactly as the server reports it. `parlour
  doctor` lists what is being served next to what is configured, which is
  the usual mismatch after loading a different model in LM Studio. A managed
  server answers to the catalogue id, so the two only differ when the model
  named was never fetched.
- **`local.timeoutMs`** applies to each completion. A model that regularly
  runs past it is too big for the machine, and with `cloud.onLocalFailure`
  on, every timeout turns into a cloud answer, which is slower and not
  private.
- **`cloud.enabled: false`**, or simply no `ANTHROPIC_API_KEY`, keeps
  everything local. The escalation tool is not offered, the persona stops
  telling the model to hand over, and it answers everything itself with the
  house tools still in hand, including the questions it probably should not.
- **`maxToolRounds`** stops a model that keeps calling tools. Six is enough
  for "turn the kitchen and hall lights off and set a timer".
- A hosted OpenAI-compatible endpoint works as the local model too: add
  `"apiKeyEnv": "SOME_NAME"` naming a variable in `secrets.env`.

### Through the AI SDK instead

Either slot can be filled by `"provider": "ai-sdk"`, which reaches the same
two back ends through Vercel's AI SDK rather than through Parlour's own
clients:

```json
{
  "llm": {
    "local": { "provider": "ai-sdk", "backend": "openai-compatible", "baseUrl": "http://127.0.0.1:8920/v1", "model": "qwen2.5-7b-instruct" },
    "cloud": { "provider": "ai-sdk", "backend": "anthropic", "model": "claude-opus-5", "effort": "low", "webSearch": true }
  }
}
```

The loop does not move. Tools are handed to the SDK without an `execute`, so
it returns the calls rather than running them, and the tool rounds, the
escalation and the request deadline stay in Parlour. What changes is who
keeps up with the two APIs.

The built-in clients remain the default, because they are what a house runs
with nothing but `fetch` behind them. Reach for this one if you would rather
track one library than two APIs, or to put the SDK's own middleware in front
of a model.

## The pipeline

```json
{
  "pipeline": {
    "concurrency": 2,
    "queueDepth": 2,
    "triage": "auto",
    "maxTasks": 4,
    "timeoutMs": 45000
  }
}
```

- **`concurrency`** is how many requests are answered at once across the
  whole house. One request per client either way, so this is how many rooms
  can be answered at once rather than how hard one room can push. Two suits
  one machine with one local model; raise it if the model is hosted
  elsewhere and can take it, and the queue will still keep each room in turn.
- **`queueDepth`** is how many requests may wait in one client's lane. Past
  it, that client's oldest waiting request is dropped and nothing is said
  for it: somebody who asks twice wants the second answer.
- **`triage`** is when a request is repaired and split before it is acted
  on. `auto` reads anything compound, long or ambiguous and lets a plain
  instruction through at once. `always` costs a local round trip on every
  request and is worth it in a noisy room or with a small speech model;
  `never` sends the words to the action agent exactly as they were heard.
- **`maxTasks`** caps how many things one request may become. Four is "turn
  the kitchen and hall lights off, set a timer and tell me the forecast".
- **`timeoutMs`** is the ceiling on one whole request. It is checked between
  tool rounds and between tasks rather than mid-request, so nothing already
  with a model is abandoned; what it stops is a request still going long
  after the person has left the room.

## Search

```json
{ "search": { "provider": "searxng", "url": "http://searxng.local:8080", "maxResults": 5 } }
```

Only the local model uses this; the cloud model brings its own search.
SearXNG needs `- json` under `search.formats` in its `settings.yml`.
`"provider": "brave"` with `BRAVE_API_KEY` in `secrets.env` is the hosted
alternative, and `"provider": "none"` leaves the local model without a search
tool.

## Logging

Set `LOG_LEVEL` in `secrets.env` (or the environment) to `debug`, `info`,
`warn` or `error`. `debug` prints every transcription time and every tool
call with its arguments, which is the level you want when working out why
the model did what it did. Logs from the service land in
`~/Library/Logs/parlour/agent.log` and `whisper.log`, and
`parlour service logs --lines 200` prints the tail of both.
